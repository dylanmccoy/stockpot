## Question

The owner has not used the app for real yet — the ordering instinct behind this
whole route was explicitly a guess, and there is no data in the database. Three
map tickets (04, 05, 07) are decisions that should be answered by evidence
rather than guessed now.

Not a decision — manual work. HITL: only the household can generate this.

### Checklist

Once the deployment track has landed, cook from the app for a few weeks and
keep a running note of:

1. Every moment something took more taps or more typing than it should have.
2. Every quantity that displayed in a unit that made you do mental arithmetic
   (the known case: add `2 lb`, the grocery list asks for `453.592 g`).
3. Every ingredient that failed to match inventory when it obviously should
   have (the known case: recipe `onion, diced` vs inventory `onion`).
4. Whether inventory stayed accurate — and if it drifted, what caused the
   drift: forgetting to log shopping, forgetting to cook-deduct, or wanting to
   undo something already applied.
5. Anything annoying that is in none of the project's documents.

### Answer records

The friction list, mapped onto the existing `features.md` catalogue where it
matches. Item 4's answer is what ticket 07 needs. Item 5 is what would
graduate the map's "whether a fifth track exists" fog.
